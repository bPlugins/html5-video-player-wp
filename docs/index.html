HTML5 Video Player: Introduction

HTML5 Video Player is a responsive, no-code video player for WordPress powered by Plyr. Embed self-hosted MP4, WebM, and OGG files, YouTube and Vimeo links, video from connected cloud storage, and adaptive HLS or MPEG-DASH streams, then brand every control to match your site.

Upgrading? What's New in 2.14.0 lists the Audio Player block, the new Style tab, and the settings that no longer get dropped when a site moves from Free to Pro.

What You Get

  • Any source: Media Library files, direct URLs, YouTube, Vimeo, cloud storage, and live streams.
  • Audio too: an Audio Player block with eight skins and waveforms, plus album playlists Pro. New in 2.14.0.
  • Every editor: Gutenberg blocks, a Classic metabox editor, shortcodes, PHP templates, and an Elementor widget.
  • Full control of the player: 16 control buttons, 7 skins, brand color, aspect ratio, and playback rules.
  • Engagement features: popup player, watermark, branding overlay, end screen, chapters, and email capture. (Pro)
  • Access control: password protection and role-based visibility per video. (Pro)
  • Measurement: a built-in analytics dashboard and GA4 event tracking. (Pro)

How These Docs Are Organized

There are two things to understand: where you build a player and where you display it. Most settings are identical either way.

  • What's New in 2.14.0 summarizes the upcoming release, which adds the audio block and repairs the Free to Pro upgrade.
  • Creating Players covers the two player editors, how to choose between them, and presets.
  • Video Sources and Player Setup document one source or option panel per page.
  • Features has one page per Pro feature, matching the tabs in the player editor.
  • Quick Player is a separate path: one inline shortcode, no saved player.
  • Usage holds the shortcode reference, editors and page builders, analytics, and global settings.

Saved players are stored as posts of the videoplayer post type, playlists as h5vpplaylist, and captured emails as h5vp_submited_email. Every saved player is embedded with the same shortcode: [html5_video id='123'].

What's New in 2.14.0

Version 2.14.0 adds an Audio Player block, gathers the sizing options into a new Style tab, and repairs several settings that were being dropped when a site upgraded from Free to Pro.

Important

Version 2.14.0 is an upcoming release. At the time of writing it sits on a test branch and has not been merged or shipped to WordPress.org, so treat everything on this page as a preview of the next release rather than something you can install today.

New: Audio Player Block

A block called HTML5 Audio Player (html5-player/audio) now sits alongside the video blocks in the Media category. It plays a single file or a whole album, in one of eight skins, with an optional real waveform. The block and three of its skins are free; the remaining five skins and the album playlist need Pro.

  • Eight skins: Modern Bar, Waveform, and Compact Pill in the free plugin, plus Podcast Card, Vinyl Record, Hero Cover Card, Studio Deck, and Vertical Card with Pro.
  • Audio playlists Pro: multiple tracks with three queue layouts, track numbers, thumbnails, and autoplay-next.
  • Track details: title, artist or podcast host, and cover artwork, per track.
  • Your own styling: width, border radius, background, and text color.

See the Audio Player group for the full documentation.

New: A Style Tab in the Classic Editor

The Classic metabox editor gains a twelfth tab, Style, holding Player Width, the new Alignment control, and Round Corner. Player Width moved here from the Settings tab, so sizing and shape now live in one place.

Fixed: Settings Lost When Upgrading from Free

Several settings created under the free plugin were being ignored once a site upgraded to Pro. All of these now carry over, and none of them need the player re-saving:

  • Round Corner was ignored for players built in the free plugin, which always rendered square corners. The saved value is now honored.
  • Alignment was dropped. Stored values are now normalized to left, center, right, wide, or full, and applied.
  • Subtitles set in the free plugin were invisible to Pro. Pro now reads the old single-caption fields, and a one-time migration copies them into the current subtitle list.
  • Inline iOS playback was hardcoded on. It now follows the new per-player field.
  • Playback speeds were global only. A player can now carry its own list.

See Upgrading from Free for what to check after an upgrade.

Fixed: Free and Pro Both Active

A guard meant to stop the block class being declared twice never fired, so running the free and Pro plugins together could crash the site with a fatal error. The guard is now correct, though you should still keep only the Pro plugin active.

Also Fixed

  • Poster images: an internal value was hardcoded empty, which quietly disabled part of the poster handling. Posters now apply and re-apply reliably.
  • Skin control grouping: the code that groups the center controls now looks only inside the control bar, so skins lay out correctly on pages with other player markup.
  • PHP 8.1 notices: a [video_player] shortcode with no id, sitting on a page next to a shortcode that has one, no longer triggers deprecation notices.
Note

The official changelog for 2.14.0 lists only the audio block plus the Round Corner and Alignment fixes, and it names four audio skins. This page follows the code, which ships eight skins and the additional fixes above.

Quick Start: Your First Player

Create a player, copy its shortcode, and put it on a page. Four steps, about two minutes.

Step 1 - Pick Your Editor (First Run Only)

On first activation the plugin asks whether you prefer the Classic metabox editor or the Gutenberg block editor. Either choice produces the same player and the same shortcode, so pick whichever feels familiar. You can change it later under Settings.

Step 2 - Create the Player

  1. Go to Html5 Video Player -> Add New Player.
  2. Give the player a descriptive title.
  3. In the Media tab or panel, keep the source set to Library or CDN and click Add Video to upload or select an MP4 file.
  4. Optional: set a Video Thumbnail so visitors see a poster before playback.
  5. Adjust Auto Play, Muted, or Repeat if you need them.
  6. Click Publish or Save.

Step 3 - Copy the Shortcode

Once saved, the player gets an ID and a shortcode box appears with a copy button:

[html5_video id='123']

Step 4 - Place It on a Page

  1. Edit any post, page, or widget area.
  2. Paste the shortcode where the video should appear.
  3. Update the page and view it on the front end.

You will see a responsive player with your chosen controls. Click play to confirm playback, then resize the window to watch it adapt.

Where to Go Next

  • Not sure which editor to use? See Choosing Your Editor.
  • Using YouTube, S3, or a live stream? Start in Video Source Types.
  • Want one inline shortcode instead of a saved player? See Quick Player.
Tip

If you run a caching plugin such as WP Rocket, LiteSpeed Cache, or W3 Total Cache, clear the cache after saving a player so visitors get the latest settings.

Choosing Your Editor

A saved player can be built in the Classic metabox editor, a tabbed settings panel, or in the Gutenberg editor, which is block-based with a live preview. Both produce exactly the same [html5_video id='123'] shortcode; only the way you configure the player differs. One setting decides which one opens.

Set Your Editor in Settings

  1. Go to Html5 Video Player -> Settings.
  2. Open the Shortcode & Tools group and select Shortcode/Player.
  3. Toggle "Use the block editor for new players": on opens Add New Player in Gutenberg, off opens the Classic metabox screen.
  4. Save. The next player you create uses that editor.
Note

Players remember their editor. Which editor a player uses is recorded when it is created (in the isGutenberg post meta), so a player built in Gutenberg always reopens in Gutenberg and one built in the Classic screen always reopens there. Flipping this setting only affects players you add from that point on.

Where Elementor Fits

This setting only controls the player editor. Elementor is a separate path: its HTML5 Video Player widget configures a video in place on the page, without creating a saved player or a shortcode. A few options, including the SEO fields and password protection, are not available in the widget.

Same Shortcode, Same Features

Almost everything in Video Sources, Player Setup, and Features is available in both player editors, and whichever you pick, the embed code and the front-end result are the same. Classic presents the options as tabs and Gutenberg as sidebar panels, with two real differences:

  • Some panels move. The end screen, watermark, and email capture are their own tabs in Classic, but in Gutenberg they live inside the preset editor once a preset is applied.

Creating vs Embedding: Do Not Mix Them Up

Building a player under Add New Player creates a saved, reusable player with an ID. Inserting the same block directly into a post configures a one-off video for that post only, with no shortcode and no reuse. If you want one player in several places, build it as a saved player and embed [html5_video id='123'].

Tip

Working in Gutenberg? Set up controls, skin, and features once in a preset, then apply it to every new player instead of repeating the configuration.

Presets Pro

A preset is a reusable bundle of player settings. Build a look once, name it, and apply it to any number of players.

Not available in Classic editor

Presets are a block-editor feature. The Classic metabox editor has no Presets tab, and a preset cannot be applied to a player built there or to the [html5_video id='123'] shortcode it produces. Build the player in Gutenberg if you want it to follow a preset.

Not available in Elementor

The widget cannot create or apply a preset. Set each option on the widget directly, or configure it on a saved player in Gutenberg or the Classic editor, then drop that player's [html5_video id='123'] shortcode into an Elementor Shortcode widget. The player keeps every setting you gave it.

Creating a Preset

  1. Select the player block and open the Presets panel in the sidebar, then click Add New Preset.
  2. The full-screen preset editor opens with Controls, Settings, Watermark, Style, End Screen, and Email Capture panels, a Skin selector, and a live preview.
  3. Configure the options you want to standardize, name the preset clearly, then click Create Preset.

What a Preset Covers

  • Controls: which of the 16 buttons appear.
  • Settings: playback rules, preload, seek time, and aspect ratio.
  • Skin: one of the 7 control-bar designs.
  • Style: width, corner radius, and brand color.
  • End Screen: the closing call to action.
  • Watermark and Email Capture: the engagement features you want on every video.

Applying a Preset

Select the preset in any player Presets panel and its settings apply immediately. Presets live in their own database table and are shared across all players, so updating one updates every player that uses it.

Media Library Files

  1. Open the Media tab or panel in the player editor.
  2. Keep Video Source set to "Library or CDN source".
  3. Click Add Video and upload a file, or pick one that is already in the Media Library.
  4. Save the player.

External and Direct URLs

Instead of uploading, paste a direct file URL into Source URL. Anything publicly reachable works: your own server, object storage, or a CDN. Bunny CDN links are detected automatically.

Tip

Hosting video outside WordPress keeps your backups small and your hosting bill predictable. Serve files over HTTPS so they never trip mixed content warnings.

Choosing the Right Source

  • Small library, low traffic: upload to the Media Library.
  • Large files or high traffic: use a CDN or S3 so your web server is not serving video.
  • Video already on YouTube or Vimeo: paste the link and keep your own controls.
  • Live or adaptive delivery: use an HLS or DASH manifest.

Cloud Storage: S3, Bunny, Drive & Dropbox Pro

Serve videos from external cloud storage so large files never touch your WordPress hosting, and browse your buckets without leaving the editor.

Cloud storage is handled by Cloud Storage for bPlugins (cloud-storage-for-bplugins), a Pro extension. You connect each provider once on its own settings page, and every supported bPlugins plugin on the site shares that configuration, so there is no per-plugin copy of your keys.

Installing the Extension

  1. Go to Html5 Video Player -> Settings -> Extensions.
  2. Find Cloud Storage and enable it.
  3. Open the new Cloud Storage screen from the admin menu.
Note

While the extension is active it takes over cloud storage completely: the plugin’s own AWS S3 settings section disappears, and URL signing for every provider is handled by the extension instead. Without it the plugin falls back to its built-in AWS S3 section, which supports Amazon S3 only.

Connecting a Provider

Each provider needs its own credentials, entered once on its own tab. Every tab ends with a Test connection button, so use it before saving and a typo shows up straight away instead of during playback.

Picking a File in the Editor

Not available in Elementor

The widget's Video Source offers only Library or CDN Source, Youtube, and Vimeo, so there is no cloud picker. Build a saved player with a cloud source, then drop its [html5_video id='123'] shortcode into an Elementor Shortcode widget.

  1. Edit the player and open the Media tab.
  2. Insert the Cloud Video Player block, or select an existing player block and open its Media panel.
  3. Set Video Source to Cloud Storage. Without the extension the same button reads AWS S3 File Manager.
  4. Choose the provider in the block placeholder. The option is hidden while the Cloud Storage extension is inactive.
  5. Browse the connected storage in the picker and select your video.
  6. Save the player.

With the extension active the picker button always renders, and the picker itself prompts you if nothing is connected yet. Without it, the button only appears once all four legacy AWS fields are filled in.

Bunny and Other CDNs Without Credentials

A public CDN URL needs no connection at all. Paste it as a direct source in the Library or CDN source field and the plugin plays it, including b-cdn.net links. Connect the Bunny providers when you want signed URLs, or want to browse and pick files from inside the editor rather than pasting addresses.

Protecting Cloud URLs

Playback URLs are signed and expire after the lifetime you set, and the address is encoded in the page markup so it does not appear in plain view. Treat encoding as a deterrent rather than access control: pair it with password protection or role restrictions when the content is paid.

Tip

Give the storage user read-only access to the single bucket that holds your videos, and keep the signed URL lifetime short. Never reuse an administrative key here.

HLS & MPEG-DASH Streaming

Serve adaptive bitrate streams that adjust quality to each viewer connection, so playback stays smooth on slow networks and sharp on fast ones.

How to Use a Stream

There is nothing to switch on. A stream is an ordinary video source: paste the manifest URL where you would paste an MP4 link, and the plugin does the rest.

  1. Edit the player, open the Media tab, and keep Video Source on "Library or CDN source".
  2. Insert the HTML5 Video Player block and open its Media panel.
  3. Select the widget, open the Settings section, and keep Video Source on "Library or CDN Source".
  4. Paste the manifest URL as the source: a .m3u8 file for HLS, or a .mpd file for MPEG-DASH.
  5. Save and view the page. The right library loads automatically.

The plugin reads the file extension off the source URL. A .m3u8 address loads hls.js, a .mpd address loads dash.js, and each library is enqueued only on pages that actually contain that kind of stream, so ordinary videos stay lightweight.

Note

HLS works in the free plugin, which ships hls.js. MPEG-DASH is Pro: the free build has no dash.js, so a .mpd source will not play until Pro is active.

Note

Because detection is by extension, a manifest served from an address that does not end in .m3u8 or .mpd is treated as an ordinary file and will not play. Streams work the same way in playlist entries and in the Quick Player shortcode.

Server Requirements

  • HTTPS: an HTTPS site cannot load an HTTP manifest. Serve the stream over HTTPS.
  • CORS: the streaming server must send Access-Control-Allow-Origin so the browser may fetch segments.
  • Reachable segments: the manifest and its segment files must be publicly readable.

Note

Auto-Complete on Watch

When a learner has watched enough of a lesson video, the lesson is marked complete through the LMS's own API, so certificates, course progress, and completion emails all behave exactly as if the learner had clicked Mark Complete themselves.

"Watched enough" is enforced, not assumed. Dragging the scrub bar to the end earns nothing:

  • Credit accumulates from real elapsed time. Seeking skips video, not the clock, so a jump to the end still leaves the watch time at a few seconds.
  • Fast playback is capped. Speeds up to the configured ceiling (2x by default) earn full credit; anything faster is credited at the ceiling rate.
  • A hidden tab earns nothing. With Focus Mode on, a video left playing in a background tab accrues no credit. Audio players are exempt, since background listening is what audio lessons are for.
  • The server decides. The browser only reports watch time; the completion decision is recomputed on the server from its own stored figures, so a forged "finished" claim cannot outrun real time.

Progress & Cross-Device Resume

Watch position is stored on the server per learner, per lesson, per player, so a learner who stops halfway on a laptop resumes from the same spot on a phone. On lesson pages this replaces the player's own browser-local Save State option, so the two can never disagree; on ordinary pages the player's own setting is left untouched.

Enrollment Gating

An unenrolled visitor never receives the video URL. The player is not hidden with CSS or blocked by an overlay — it is never rendered at all, and no signed media URL is generated, so there is nothing to recover from the page source or the network tab. The visitor sees a locked placeholder instead.

A well-behaved LMS already protects its own lesson pages, so the gate earns its keep everywhere else: players placed in ordinary posts, page builders rendering lesson content outside the LMS template, course curriculum previews, the [html5_video] shortcode, and feeds.

Tip

To exclude one player from tracking and gating entirely, add the CSS class h5vp-lms-ignore to it in the block's Advanced panel.

Reports

The Video LMS screen opens on Reports & Analytics: per-course engagement, a student progress matrix showing every enrolled learner against every video lesson, and a per-lesson drop-off curve that shows where viewers stop watching. Rows can be exported to CSV.

Good to Know

  • YouTube and Vimeo are tracked by a different route than self-hosted video, because the provider replaces the media element with an iframe. If an optimization plugin defers or delays this extension's script, embed tracking stops working — it fails open, so nothing locks and the learner is simply untracked rather than stuck.
  • Live streams are never tracked or gated for completion, since they have no fixed duration to watch a percentage of.
  • Background playback has a signature. A learner who lets the video run in a hidden tab shows a high drop-off-curve position but 0% watched, and does not complete. The two figures disagreeing is background playback, not a fault.

Play equirectangular 360°, 180° and stereoscopic video on your own site. Visitors drag to look around on desktop, swipe on a phone, tilt the handset to pan with the gyroscope, or drop into a Cardboard split-screen headset view — no YouTube, no third-party embed.

360° playback is a separate module rather than a built-in feature, because it carries its own WebGL rendering stack (Video.js and videojs-vr, about 1.4 MB) that ordinary flat videos should never pay for. Install it once and it loads only on pages that actually contain a 360° player.

Installing the Module

  1. Go to Html5 Video Player -> Extensions and open the Modules tab.
  2. Find 360° & VR Video Support and click Install. It is enabled as soon as it is installed.
  3. A new 360° Videos item appears in the Html5 Video Player menu, and a 360° VR Video block appears in the editor's inserter.
Note

The module needs HTML5 Video Player Pro 2.13.0 or newer with a premium licence. If your host plugin is older, the module will not appear as installable.

The 360° VR Video Block

Insert 360° VR Video anywhere you would insert a normal block — straight into post or page content, or inside the player wrapper alongside Video, YouTube and Vimeo. Point it at an equirectangular file from the Media Library or paste a URL, and it plays as a sphere on the published page.

The editor shows a still preview — the poster image with a play glyph and a projection badge — instead of a live sphere. The WebGL stack loads on the front end only, so the editor stays fast no matter how many 360° blocks a page holds. Press Preview or view the published page to look around.

Supported Sources

Self-hosted MP4, WebM and Ogg, plus HLS (.m3u8) and DASH (.mpd) streams. Files served from cloud storage work too, and streaming URLs keep the plugin's usual obfuscation.

Important

A direct video file hosted on another domain must be served with CORS headers (Access-Control-Allow-Origin). Without them the browser refuses to let WebGL read the frames and the sphere stays blank. HLS and DASH streams are unaffected.

Good to Know

  • YouTube and Vimeo cannot be made 360° by this module. They render inside the provider's iframe, which gives no pixel access for WebGL. Their own 360° players handle it instead.
  • Popup and password-protected players keep the normal renderer. Their open and unlock flows live in the main player app, so a 360° class on one of them is ignored. Use a 360° VR Video block or the [h5vp_360] shortcode for those pages.
  • Some Pro features do not apply to a 360° player — overlay, sticky, save state, analytics and end screens belong to the normal renderer. Core playback options (poster, autoplay, loop, speeds, captions, start time, brand color) are carried over.
  • No WebGL, no sphere. On a browser or device without WebGL the player shows a short message rather than playing the video flat and distorted.
  • Assets are cached, not re-downloaded. The rendering stack is copied once into your uploads folder and served from there, so a visitor downloads it on their first 360° page and never again.

Common Issues

The problems that come up most often, and what to check first for each one.

Autoplay Is Not Working

Browsers block autoplay with sound, so start by checking Muted. Then work through the causes:

  • Muted is off: switch on both Auto Play and Muted. Browsers allow muted autoplay.
  • A watermark is enabled: watermarks disable autoplay by design. Remove the watermark, or accept click-to-play.
  • You want a friendlier start: use Autoplay When Visible on Screen so playback begins when the viewer reaches the video.
  • Mobile data saver: some phones block autoplay regardless of settings. Always design so the video works when tapped.

The End Screen Never Appears

The end screen needs the video to end and stay ended. Switch off Repeat and Reset On End for that player, then play it through to the finish.

Subtitles Will Not Upload or Display

Check the upload first, then the display:

  • The Media Library rejects the file: a security plugin is blocking .vtt uploads. Switch on "Allow .vtt uploads" under Settings -> Convert .srt to .vtt.
  • The file uploads but shows nothing: confirm it is valid WebVTT starting with the WEBVTT header line, and convert .srt files with the built-in converter.
  • No captions button appears: switch on the Captions control in the Controls tab.
  • The video is a stream: HLS and DASH carry their own text tracks, so the Subtitle panel does not apply.

Download or PIP Button Missing

PIP, AirPlay, and Download do not work with YouTube or Vimeo sources and are hidden for them. For self-hosted video, confirm the control is switched on in the Controls tab.

Quality Switcher Shows the Wrong Resolution

The Size value is a label, not a measurement, so it must match the file you paired with it. Re-check each row in the Qualities panel, and remember that streams handle their own quality levels.

Conflict with Another Video Plugin

WordPress and other plugins also register [video]. Switch on Disable [video id] shortcode under Settings -> Shortcode/Player, then embed with [html5_video id='123'] instead. Both render the same player.

Protected Video Shows for Everyone (or No One)

  • It shows for everyone: you are testing while signed in as an administrator. Check in a private browser window.
  • It shows for no one: re-read the Who Can See This Video? setting. Logged-out Users hides the player from signed-in members, which is easy to set by accident.
  • The source is YouTube or Vimeo: password protection does not apply to those, because the files stay reachable on their platforms.

Nothing Renders at All

  • "No Video Added": the Quick Player has no source. Add src, file, or mp4.
  • The shortcode prints as text: the plugin is deactivated, or the shortcode sits inside a code block.
  • A blank space appears: confirm the player ID exists and is published, then clear your caching plugin.

Settings Missing After Upgrading from Free

Corner rounding, alignment, or captions that worked under the free plugin can disappear once a site moves to Pro. Version 2.14.0 fixes all three. If you are on it and something is still missing, see Upgrading from Free for the per-setting checks.

The Site Crashes with Free and Pro Both Active

Running the free and Pro plugins at the same time could produce a fatal error, because a guard meant to prevent a duplicate class declaration never fired. It is fixed in 2.14.0, but the fix is not a licence to run both: deactivate the free plugin and keep only Pro.

PHP Deprecation Notices from a Quick Shortcode

On PHP 8.1 and later, a [video_player] shortcode written without an id, sitting on a page beside a shortcode that has one, could emit deprecation notices. Version 2.14.0 skips those entries instead of passing an empty value along. If you see the notices, update the plugin rather than editing your shortcodes.

Alignment Does Nothing

Alignment moves the player inside its container, so it needs spare room to work. Set a Player Width narrower than the content column and the alignment takes effect. A full width player looks identical on every alignment setting, which is expected.

The Audio Waveform Looks Generic

The Waveform skin draws the real shape of the audio by fetching and decoding the file. When the file cannot be read across origins, or the format cannot be decoded, the player keeps a placeholder waveform and playback continues normally. Serve the audio from your own domain, or send CORS headers from your CDN, to get the true shape.

Theme or Plugin Conflicts

The plugin works with most themes and plugins, but conflicts happen. To identify one, switch to a default theme such as Twenty Twenty-Four and deactivate other plugins one at a time until the player behaves. Report the conflict to support and a fix usually follows in a plugin update.

Reporting Security Issues

Report security bugs through the Patchstack Vulnerability Disclosure Program linked in the plugin readme. The Patchstack team handles verification, CVE assignment, and notifying the developers.

Upgrading from Free

Moving a site from the free plugin to Pro used to leave a few settings behind. Version 2.14.0 fixes each of them, and this page tells you what to check.

Before You Upgrade

  1. Take a backup, as you would for any plugin change.
  2. Note which players use captions, corner rounding, or alignment, so you can spot-check them afterwards.
  3. Install and activate the Pro build, then connect your license.
  4. Deactivate the free plugin. Keep only Pro active.
Important

Do not leave the free and Pro plugins active together. Before 2.14.0 a faulty guard meant both being active could crash the site with a fatal error over a duplicated class. The guard is fixed, but the two editions still overlap and only Pro should run.

What Now Carries Over

Setting What Used to Happen In 2.14.0
Round Corner Ignored. The player rendered square corners whatever the saved value. The saved radius is applied, with no re-saving needed.
Alignment Dropped entirely. Normalized to left, center, right, wide, or full, then applied.

  • A player that had captions: open its Subtitle panel and confirm a row is filled in.
  • A player with rounded corners: view it on the front end; the corners should match the Style tab value.
  • A narrower player: confirm its alignment now takes effect. Alignment only shows when the player is narrower than its container.
  • Your caching plugin: clear it, so visitors get the corrected markup.

Nothing needs rewriting. Saved players keep their IDs and shortcodes, and audio blocks placed under the free plugin keep working because Pro registers the same block name, html5-player/audio.

Frequently Asked Questions

Short answers to the questions we are asked most.

Common Questions

What video formats can I play?

Self-hosted MP4, WebM, and OGG files, plus YouTube, Vimeo, and HLS (.m3u8) streams. Pro adds MPEG-DASH (.mpd) streams and, through the Cloud Storage extension, Amazon S3, Bunny, Google Drive, and Dropbox. MP4 with H.264 video and AAC audio is the most universally compatible choice.

How many players can I publish?

There is no limit. Create unlimited players and playlists across posts, pages, widgets, and templates.

What WordPress and PHP versions are required?

WordPress 6.5 or higher and PHP 7.4 or higher. The Pro version needs PHP 8.1 or higher. Check yours under Tools -> Site Health -> Info -> Server.

Will it work with my theme and my other plugins?

It is compatible with most themes and plugins. If you find a conflict, test with a default theme to confirm it, then contact support; fixes ship regularly in plugin updates.

What does Pro add?

Skins and presets, playlists, quality switching and multiple subtitles, chapters, popup player, watermark, branding overlay, end screen, password and role-based access, email capture with CRM integrations, video SEO schema, VAST ads, GA4 analytics, streaming and cloud sources, plus custom CSS and player translation.

Will my free players survive upgrading to Pro?

Yes. Every player and shortcode keeps working, and existing free players are migrated automatically. Version 2.14.0 also repairs the settings that used to be dropped on upgrade: corner rounding, alignment, and captions saved under the free plugin now carry over. Keep only the Pro plugin active after upgrading, and see Upgrading from Free for the checks worth making.

Can I play audio files, not just video?

Yes, from version 2.14.0. The HTML5 Audio Player block plays a single file or a whole album in one of eight skins, including a real waveform, and it is available in both the free and Pro editions. See the Audio Player group for the details.

Is version 2.14.0 available now?

Not yet. At the time of writing 2.14.0 sits on a test branch and has not been merged or released to WordPress.org, so the audio block, the Style tab, and the upgrade fixes are all previews of the next release.

Can I move players between sites?

Yes. Switch on Import/Export under Settings -> Shortcode & Tools to move players and presets from one site to another.

Which editor should I use, Classic or Gutenberg?

Either. Both produce the same player and the same shortcode. Gutenberg adds a live preview and the full-screen preset editor; the Classic screen presents everything as tabs. See Choosing Your Editor for a comparison.

Why does the Elementor widget lack some options?

The widget has no SEO fields and no password protection. Configure a saved player with those settings and drop its shortcode into an Elementor Shortcode widget instead.

What is the difference between [html5_video] and [video_player]?

[html5_video id] renders a saved player you built in the editor, so all its settings come from that player. [video_player] is the Quick Player: no saved post, every option passed inline as an attribute. Use the first for players you reuse, the second for one-off videos.
